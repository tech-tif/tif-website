## 1. How the site works (read this first)

- The text of the site lives in three JSON files inside `content/`
  (`en.json`, `hi.json`, `mr.json`). **This is the only place you edit text.**
- A small program, `build.py`, reads those JSON files and generates the three
  web pages (`index.html`, `hi/index.html`, `mr/index.html`).
- You then upload (push) the whole folder to GitHub, and GitHub Pages serves it
  at your domain for free.

So the mental model is: **edit JSON → run build.py → push to GitHub → live.**

Two important rules:
- **Never hand-edit `index.html`, `hi/index.html` or `mr/index.html`.** They are
  regenerated by `build.py` and your manual changes would be lost.
- **Do not use em dashes ( — ) anywhere.** Use commas, colons or periods.

## 3. One-time setup on your computer

You need three free tools. Install them once.

1. **Git** (version control, required to push to GitHub)
   - Windows / Mac: download from https://git-scm.com/downloads and install with
     default options.
2. **Python 3** (needed to run `build.py` and to preview locally)
   - Download from https://www.python.org/downloads. On Windows, tick
     **"Add Python to PATH"** during install.
   - Check it works: open a terminal (Command Prompt on Windows, Terminal on Mac)
     and run `python --version` (or `python3 --version`).
3. **A code editor** to edit the JSON files
   - Visual Studio Code is recommended: https://code.visualstudio.com

Optional but strongly recommended for non-developers:
- **GitHub Desktop** (https://desktop.github.com) gives you a friendly window with
  buttons instead of typing Git commands, and it handles login for you.
- A **GitHub account**: https://github.com (free).

## 4. Getting the files and previewing locally

1. Unzip `tif-website.zip`. You will get the `tif-website` folder shown above.
   Keep this folder somewhere safe, for example `Documents/tif-website`.
2. Preview the site on your own computer before publishing. The pages use paths
   like `/css/...` and `/assets/...`, so you must open them through a small local
   web server, **not** by double-clicking the HTML file.
   - Open a terminal, move into the folder, and start the server:
     ```bash
     cd path/to/tif-website
     python -m http.server 8000
     ```
   - In your browser open:
     - English: http://localhost:8000/
     - Hindi:   http://localhost:8000/hi/
     - Marathi: http://localhost:8000/mr/
   - Press `Ctrl + C` in the terminal to stop the server when done.

If the styling looks broken when previewing, you almost certainly opened the file
directly instead of using the local server above.

## 5. Creating the GitHub repository

1. Sign in at https://github.com.
2. Click the **+** (top right) → **New repository**.
3. Repository name: for example `tif-website` (or `website`).
4. Keep it **Public** (required for free GitHub Pages).
5. Do **not** add a README, .gitignore or license here (you already have files).
6. Click **Create repository**. Leave this page open; you will need the repo URL,
   which looks like `https://github.com/<your-username>/tif-website.git`.

## 6. Pushing the site to GitHub — Option A: GitHub Desktop (easiest)

Use this if you prefer buttons over typing.

1. Install and open **GitHub Desktop**, sign in with your GitHub account.
2. Menu **File → Add local repository** and choose your `tif-website` folder.
   - If it says the folder is not a Git repository, click **"create a repository"**
     when offered, then continue.
3. In the left panel you will see all files listed as changes. At the bottom left,
   type a summary like `Initial website` and click **Commit to main**.
4. Click **Publish repository** (top). Untick **"Keep this code private"** so it is
   public, pick the repo name, and publish.
5. Done. Your files are now on GitHub. For future updates you will just
   **Commit** then **Push** from this same window.

Skip to section 8 (Publishing).

## 7. Pushing the site to GitHub — Option B: command line

Use this if you are comfortable with a terminal.

1. Open a terminal in the `tif-website` folder:
   ```bash
   cd path/to/tif-website
   ```
2. Set your identity once (first time only, on this computer):
   ```bash
   git config --global user.name  "Your Name"
   git config --global user.email "treeindiafoundation1@gmail.com"
   ```
3. Initialise the repo, add files, make the first commit:
   ```bash
   git init
   git add .
   git commit -m "Initial website"
   git branch -M main
   ```
4. Connect it to the GitHub repo you created and push:
   ```bash
   git remote add origin https://github.com/<your-username>/tif-website.git
   git push -u origin main
   ```
5. **Login note:** GitHub no longer accepts your account password on the command
   line. When prompted for a password, paste a **Personal Access Token** instead:
   GitHub → **Settings → Developer settings → Personal access tokens → Tokens
   (classic) → Generate new token**, tick the **repo** scope, copy the token, and
   use it as the password. (GitHub Desktop avoids this entirely.)

## 8. Publishing with GitHub Pages

1. On GitHub, open your repository → **Settings** → **Pages** (left sidebar).
2. Under **Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: **main**, Folder: **/ (root)** → **Save**.
3. Wait about a minute, then refresh. GitHub shows a link like
   `https://<your-username>.github.io/tif-website/`. Open it to confirm the site
   loads. (The pretty domain comes next.)
4. `/hi/` and `/mr/` work automatically because they are real folders each with
   their own `index.html`. No extra routing is needed.

## 9. Connecting the custom domain (treeindiafoundation.org)

Your repo already contains a `CNAME` file with `treeindiafoundation.org`, which
tells GitHub the domain. You now point the domain at GitHub from GoDaddy.

1. **On GitHub:** Settings → Pages → **Custom domain** should already show
   `treeindiafoundation.org` (from the CNAME file). If it is empty, type it and
   **Save**.
2. **At GoDaddy** (Domain → DNS → Manage DNS), set these records:

   | Type  | Name (Host) | Value                     | TTL     |
   |-------|-------------|---------------------------|---------|
   | A     | @           | 185.199.108.153           | Default |
   | A     | @           | 185.199.109.153           | Default |
   | A     | @           | 185.199.110.153           | Default |
   | A     | @           | 185.199.111.153           | Default |
   | CNAME | www         | `<your-username>.github.io` | Default |

   - The four A records point the bare domain (treeindiafoundation.org) to GitHub.
   - The CNAME sends www to your GitHub Pages. Replace `<your-username>` with your
     actual GitHub username. Do not put a trailing dot unless GoDaddy adds it.
   - Remove any old "Parked", "Forwarding" or conflicting A/CNAME records for @ and
     www that GoDaddy added by default.
3. **Wait for DNS to propagate** (often 30 minutes, can be up to a few hours).
4. Back on GitHub Pages, once the check passes, tick **Enforce HTTPS**. This gives
   the site a free SSL certificate (the padlock). The certificate can take a little
   while to issue; if the checkbox is greyed out, wait and refresh.
5. Test all three: https://treeindiafoundation.org/ , /hi/ , /mr/ .

## 10. Editing website content

All visible text is in `content/en.json`, `content/hi.json`, `content/mr.json`.
The keys (the names on the left) are identical across the three files, so the same
field is easy to find in each language.

Steps:
1. Open the language file in your editor, for example `content/en.json`.
2. Change only the **values** (the text on the right of the colon). Keep the keys,
   quotes, commas and brackets exactly as they are.
   - Example: to change the hero headline, find `"h1": "Learning that reaches
     beyond the classroom"` under `"hero"` and edit the sentence.
3. If you changed English, make the matching change in `hi.json` and `mr.json` too,
   so all three stay consistent.
4. Regenerate the pages:
   ```bash
   cd path/to/tif-website
   python build.py
   ```
   You should see `wrote ./index.html`, `wrote hi/index.html`, `wrote mr/index.html`.
5. Preview locally (section 4) to check it looks right.
6. Push the change (section 12).

Tips:
- Keep the JSON valid: every value in quotes, items separated by commas, no comma
  after the last item in a list. If `build.py` errors, it usually points to the
  line with the mistake.
- Some items are lists (for example the seven learner outcomes or the CSR areas).
  Each has a `"t"` (title) and `"d"` (description). Edit those in place.
- No em dashes. Use commas, colons or periods.

> Reminder: GitHub Pages does not run Python. You run `build.py` on your computer,
> then push the generated HTML. This is why step 4 is required before pushing.

## 11. Reviewing and updating translations (Hindi / Marathi)

The Hindi and Marathi text was professionally drafted but should get a native
review before wide promotion (Marathi especially).

To review and correct:
1. Read the live/preview `/hi/` and `/mr/` pages, or read `content/hi.json` and
   `content/mr.json` directly.
2. To fix wording, edit the value for that key in the relevant file. Find the
   matching English key in `content/en.json` to be sure you are editing the right
   field (keys are the same across languages).
3. Keep meaning and tone aligned with the approved English; do not translate word
   for word if it sounds unnatural.
4. Run `python build.py`, preview, then push.

To add a completely new language later (for example Gujarati), tell me and I will
add the language to `build.py` (its URL folder, `html lang`, hreflang and metadata)
and create a `content/<code>.json` for you to fill in. It is a small, safe change.

## 12. The routine update loop (every time you change something)

This is the cycle you will repeat for any edit:

1. Edit the file(s) in `content/`.
2. `python build.py`
3. Preview locally (`python -m http.server 8000`) and check.
4. Save to GitHub:
   - **GitHub Desktop:** write a short summary → **Commit to main** → **Push origin**.
   - **Command line:**
     ```bash
     git add .
     git commit -m "Update <what you changed>"
     git push
     ```
5. Wait about a minute; GitHub Pages redeploys automatically. Refresh the live site.
6. If it was a meaningful content change, ping Google Search Console to re-check
   the page (section 14).

## 13. Turning the forms on (Contact / Volunteer / Partner / Donate)

The four forms are built and validated but not yet connected. Until connected they
show: *"Form not connected yet. Please email treeindiafoundation1@gmail.com."*

To activate:
1. Follow `google-apps-script/SETUP.md`. It walks you through pasting `Code.gs`
   into Google Apps Script and deploying it as a **Web App**. This creates a Google
   Sheet (one tab per form), emails an alert to treeindiafoundation1@gmail.com on
   each submission, and auto-replies to the person who submitted.
2. Copy the Web App URL it gives you and paste it into `js/config.js`:
   ```js
   window.TIF_CONFIG = { GAS_URL: "https://script.google.com/macros/s/XXXX/exec" };
   ```
3. Commit and push. No `build.py` needed here, because `config.js` is shared by all
   three pages.

Donations are currently **pledge-only** (they record intent to the sheet). For live
online payments, a payment gateway (Razorpay, PayU or CCAvenue) can be added to the
donate form later.

## 14. Google Search Console setup and re-submitting after changes

Do this once the site is live on HTTPS at the custom domain.

**First-time setup**
1. Go to https://search.google.com/search-console and click **Add property**.
2. Choose **Domain** and enter `treeindiafoundation.org`.
3. Google gives you a **TXT record** to add at GoDaddy (DNS → add a TXT record with
   Name `@` and the value Google shows). Save it, wait a few minutes, then click
   **Verify**.
4. In the left menu open **Sitemaps**, and under "Add a new sitemap" enter:
   ```
   sitemap.xml
   ```
   (Google will read `https://treeindiafoundation.org/sitemap.xml`.) Submit.
5. Use **URL Inspection** (top search bar) for each page:
   `https://treeindiafoundation.org/`, then `/hi/`, then `/mr/`. For each, click
   **Request indexing**.

**After you publish content changes**
- Re-run URL Inspection on the changed page and click **Request indexing** again so
  Google re-crawls it sooner.
- Periodically review the **Page indexing**, **HTTPS**, **Core Web Vitals** and
  **Enhancements** reports and fix anything flagged.

> Being technically indexable does not guarantee ranking or immediate indexing.
> Ranking also depends on content quality, links, authority and competition. Do not
> expect instant results; indexing can take days.

## 15. SEO features already built in

- A separate, crawlable URL per language, with the translated text present directly
  in the page source (not hidden behind JavaScript).
- Unique `<title>` and meta description for each language.
- One clear `<h1>` per page and a logical H2/H3 order.
- `rel="canonical"` per page and `hreflang` links for en / hi / mr / x-default.
- Open Graph and Twitter tags with a branded share image (`assets/TIF_og.jpg`), so
  links look good when shared on WhatsApp, LinkedIn, X, etc.
- JSON-LD structured data (NGO/Organization + WebSite + WebPage + ContactPoint)
  using only your verified details: name, URL, logo, email, phone, Pune address.
- `robots.txt` (allows crawling, references the sitemap) and a valid `sitemap.xml`.
- Descriptive image `alt` text and semantic, keyboard-accessible markup.

## 16. Troubleshooting

- **Styling is broken when previewing locally.** You opened the HTML file directly.
  Use the local server: `python -m http.server 8000`, then http://localhost:8000/ .
- **`python` not found.** Try `python3` instead, or reinstall Python with "Add to
  PATH" ticked (Windows).
- **`build.py` prints a JSON error.** You likely removed a quote or comma while
  editing a `content/*.json` file. Go to the line it mentions and fix the JSON.
- **Custom domain shows a 404 or "not found" for a while.** DNS is still
  propagating, or an old GoDaddy A/CNAME/forwarding record is conflicting. Remove
  stray records and wait.
- **"Enforce HTTPS" is greyed out.** The certificate is still being issued. Wait a
  bit and refresh the Pages settings.
- **`/hi/` or `/mr/` gives 404.** Make sure the `hi/` and `mr/` folders (with their
  `index.html`) were actually pushed to GitHub.
- **Forms say "not connected".** Expected until you paste the Apps Script Web App
  URL into `js/config.js` (section 13).
- **Git push asks for a password and rejects it.** Use a Personal Access Token, or
  switch to GitHub Desktop (section 7 note).
- **I edited index.html directly and it reverted.** Those files are generated. Edit
  `content/*.json` and run `build.py` instead.

## 17. Maintenance checklist

- **Every edit:** edit JSON → `build.py` → preview → commit → push (section 12).
- **After content changes:** request indexing in Search Console for that page.
- **Monthly:** glance at Search Console for indexing/HTTPS/Core Web Vitals errors.
- **Before promotion:** confirm the Hindi/Marathi native review is done, and that
  the forms are connected.
- **Keep a backup:** the whole `tif-website` folder is your backup. GitHub also
  keeps the full history of every change.
